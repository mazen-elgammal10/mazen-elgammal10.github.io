Key risk exposure centered around broken object- and function-level authorization (IDOR / BOPLA) allowing unauthorized cross-account access, alongside missing mobile runtime integrity checks.

[VAPT-01] Broken Object Property Level Authorization (BOPLA)

Critical • 9.1

The profile update endpoint binds client-supplied JSON fields directly to the user entity without an allowlist, enabling privilege escalation via role injection. 

PATCH /api/v1/users/profile HTTP/1.1
Authorization: Bearer <standard_user_jwt>
Content-Type: application/json

{
  "displayName": "Mazen",
  "role": "Admin"
}

Actionable Remediation & Hardening

  • Strict DTO Allowlisting: Bind incoming request payloads to explicit Data Transfer Objects (DTOs) that exclude sensitive properties such as role or isAdmin.
  • Server-Side Object Ownership Checks: Enforce authorization middleware validating resource ownership on every object ID lookup.
  • Mobile Hardening: Enable certificate pinning, root/emulator detection, and strip hardcoded staging endpoints prior to release builds.
